# Qualifying Coaction 4.0

Tag only the exact commit that passed qualification. All 18 public packages
must declare `4.0.0`, and every required dependency version must already be
available from npm. A local dependency patch or tarball is useful for testing
a candidate, but does not establish readiness for a registry consumer. The
4.0 qualification baseline uses the published Mutative `1.3.0` selected by the
lockfile; no Mutative `1.3.1` candidate or dependency patch is required.

## Required checks

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm soak 50 1000000
pnpm soak 50 5000000
pnpm soak 50 9000000
pnpm benchmark:check
pnpm test:e2e:browser
```

`pnpm check` includes mutation tests and historical defect replay as well as
the release gate. Run it without another process editing the source: those two
checks temporarily change files and restore their original contents.

`test:packed` installs every package into its own consumer outside the
workspace. It checks all 26 code entries using Node ESM and CJS, compiles their
installed declarations with TypeScript NodeNext and Bundler resolution, and
executes a store/commit/history scenario in both module formats. Only the
package under test and its declared workspace peers are direct runtime
dependencies; unrelated Coaction packages cannot conceal a missing dependency.

The React CI matrix installs React and React DOM 18 or 19 together with the
corresponding type packages. Each version runs the React unit tests and real
Chromium, Firefox and WebKit hydration tests. Server markup is generated in
Node with an independent store; browser tests check initial and preloaded
state, StrictMode, mismatch recovery and continued subscriptions. The jsdom
hydration suite remains a separate, faster regression check.

The soak includes patch algebra, complete graph replacement and replay,
write-path fuzz, checkpoint properties, MobX async interleaving and Sync
state-machine tests. Graph qualification covers the
[supported local update contract](../architecture/core-runtime.md#draft-editing-and-complete-graph-replacement),
including cycles supplied as complete values and independent-path DAG edits.
It does not qualify creation or editing of cycles through draft references. Sync's
randomized network actions complete sequentially; dedicated unit tests cover
overlapping and stale responses. The fuzz does not claim arbitrary concurrent
network scheduling.

Run benchmarks without competing builds or test suites. Keep all frozen
floors and size ceilings unchanged, and retain results with the commit SHA,
Node version, dependency versions, soak scales and seed offsets.

## Tagging and publishing

After the final commit passes local qualification and CI:

```sh
git status --short
git tag -a v4.0.0 -m "Coaction 4.0.0"
git push origin v4.0.0
```

Publishing the GitHub Release for `v4.0.0` triggers `npm-publish.yml`; pushing
the tag alone does not publish npm packages. The workflow reruns
`check:release`, then publishes `coaction` before the integration packages.
Verify all 18 versions, their `latest` tags and npm provenance after it finishes.

An RC is optional additional user validation. If choosing one, version every
package consistently as a prerelease before qualification. The publish script
maps `4.0.0-rc.1` to the npm `rc` tag. A 3.x install count does not establish
that users have exercised the changed 4.0 contracts.
